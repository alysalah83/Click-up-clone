# A1: Monorepo + CI Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Merge the front-end and back-end repos into one pnpm + Turborepo monorepo (`apps/web`, `apps/api`), keeping the git history of both, with lint, typecheck, test and build running in GitHub Actions. Both Vercel projects must deploy from the new repo.

**Architecture:** The front-end repo becomes the monorepo, since the plan renames it on GitHub to `click-up-clone`. Its files move into `apps/web` with `git mv`. The back end's `Back-end/` folder is pulled in as `apps/api` with `git subtree split` + `git subtree add`, which keeps its commits and drops the stale `Front-end` git link. Turborepo runs the per-app scripts. No application behavior changes in this plan.

**Tech Stack:** pnpm 10 workspaces, Turborepo 2, ESLint 9 flat config, typescript-eslint 8, GitHub Actions, Vercel (two projects, each with its own root directory).

**Spec:** `docs/superpowers/specs/2026-09-28-foundation-design.md` (§0 amendments 5 and 8, §4.1)

## Global Constraints

- Free hosting only; nothing may need a credit card.
- Visual identity and app behavior must not change in this plan.
- Keep the git history of both repos. Leave the two original local folders (`D:\projects\click-up\Click-up-clone-front-end`, `D:\projects\click-up\Click-up-clone-back-end`) untouched as a backup. The only exception is a temporary branch created and deleted in Task 2.
- Package names: `@clickup/web`, `@clickup/api`. Later plans add `@clickup/shared`.
- The default branch stays `master`, because Vercel production already tracks it.
- Node: CI uses Node 24. Local is Node 25.9 with pnpm 10.33.0.
- **Never push to GitHub or change Vercel or GitHub settings without asking the user in chat first.** Task 6 steps marked 👤 are done by the user or with their explicit go-ahead.

- [ ] **Step 4: Write `docs/adr/0001-monorepo.md`**

```markdown
# ADR 0001: One monorepo for web and API

- Status: Accepted
- Date: 2026-09-28

## Context
The project started as two repositories, a Next.js front end and an Express + Prisma API. They drifted apart:
- The API had no shared request types, so the front end re-declared every shape by hand.
- The back-end repo carried a stale, empty git link to the front end.
- Cross-cutting changes (such as a new field) needed two PRs and two reviews with no single CI run.

## Decision
- Use one pnpm + Turborepo monorepo:
  - `apps/web` is the Next 16 app.
  - `apps/api` is the Express 5 API.
  - `packages/*` holds shared code; `@clickup/shared` (zod schemas) arrives in plan A2.
- Git history of both repos is kept (`git mv` for web, `git subtree` for the API).
- Each app keeps its own Vercel project, with its root directory set to the app folder.

## Consequences
- **Gain:** one CI pipeline (lint, typecheck, test, build) and atomic cross-app changes. Request schemas can be shared, so client and server validation cannot disagree.
- **Cost:** the two apps still deploy separately. API changes must stay backwards-compatible for one deploy, because a web deploy may lag the API deploy.
- pnpm's strict dependency layout surfaced phantom dependencies, which are now declared explicitly.
```
